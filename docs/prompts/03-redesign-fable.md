## 3. やること

### 3-1. メルマガ機能を「保留」にする（消さずに隠す）
- `config.js` に `NEWSLETTER_ENABLED: false` を追加する（コメントで「true にすると復活」と書く）。
- false のとき、次をすべて非表示にする（DOM から除くか `hidden`）：
  - メルマガのセクション（`#newsletter`）
  - ナビの「メルマガ登録」
  - ヒーローの「活動報告をメールで受け取る」ボタン
- **`main.js` が落ちないようにする**（今は `#nl-form` に直接 `addEventListener` しているので、要素がないとエラーになる。存在チェックを入れる）。
- true に戻したら、**今のメルマガ機能（フォーム・登録処理）がそのまま復活**すること。実際に true にして確認する。
- 代わりの行動ボタン：
  - ナビの右端：「SNSをフォロー」（`#sns` へ）
  - ヒーロー：ボタンは **1つだけ**「目指すことを読む」（`#vision` へ）
  - 活動報告セクションなどに、控えめな「活動報告を見る」「SNSをフォローする」の導線

### 3-2. デザインを作り直す（方向性 A：誠実系）
**コンセプト**：本人の表情で信頼を伝える。写真が主役で、文字と色は控えめ。生成りの紙面に、墨色の文字と、藍鼠の面。差し色は **ボタンだけ**。

**配色（CSS変数にまとめる）**

| 役割 | 色 | コード |
|---|---|---|
| 背景 | 生成り | `#F7F5F0` |
| 文字 | 墨（青みのある黒） | `#1C232B` |
| メイン（面・見出し） | 藍鼠 | `#33475B` |
| 差し色（ボタン・小さな強調だけ） | 柿 | `#C2552E` |
| 補助（区切り線・淡い面） | 灰青 | `#DCE2E6` |

- 柿色は **ボタンとごく小さな強調だけ**に使う（面積を増やさない）。白文字との組み合わせでコントラスト比 4.5:1 以上を満たすこと。足りなければ、わずかに暗くする（例：`#B8481F`）。
- **政党カラー（赤・緑・青・黄・オレンジなどの単色）が主役にならないようにする。** 所属政党の表記や党のロゴはサイトに入れない（公認の表記は本人の確認待ち）。

**フォント（Google Fonts。読み込みを軽くする）**
- 名前・大見出し：**Shippori Mincho B1**（Bold または ExtraBold）
- 小見出し・ボタン・ナビ：**Zen Kaku Gothic New**（Medium / Bold）
- 本文：**Noto Sans JP**（Regular 400 と Bold 700 のみ。行間 1.9）
- 英数字・日付・番号：**Cormorant Garamond**（数字・日付だけ。重いと感じたら Zen Kaku Gothic New の数字で代用してよい）
- 使うウェイトは最小限にし、`display=swap`、`preconnect` を付ける。**フォントは合計3ファミリーまでを目安**にする。
- 見出しには `font-feature-settings: "palt"`（プロポーショナルメトリクス）を試し、日本語の字間が詰まりすぎないか確認する。

**ファーストビュー（いちばん大事。サイトの印象はここでほぼ決まる）**
- PC（1280px）：左右 **6:4 の2分割**。
  - **右 6 割＝本人の写真を画面の端まで（フルブリード）**。角丸・影・ずらした背景板（今の `.hero-photo::before`）は **やめる**。
  - 左 4 割（上から）：小さく「佐賀県議会議員選挙 2027｜神埼市・吉野ヶ里町選挙区」→ **ふりがな（名前の上に小さく）** → **名前（特大の明朝）** → **ひと言コピー（1〜2行）** → **ボタン1つ**（柿色）。
  - リード文（長い文章）は **ファーストビューに入れない**。次の「ごあいさつ」セクションへ移す。
- スマホ（390px）：**写真を画面の上 6 割**に置き、写真の下端を背景色にやわらかく溶かす（グラデーション）→ その下に、名前、コピー、ボタン。1画面（高さ 844px）で、写真・名前・コピー・ボタンが見えること。
- 「`<h1>` は名前」にする。写真の `alt` は「森田浩文」など意味のある文字にする（装飾の場合は空 `alt` でもよいが、写真は内容なので入れる）。
- ヘッダーは軽く（ロゴ＝名前の文字だけ、ナビは細く）。スマホはハンバーガーメニュー（今の仕組みを生かしてよい）。

**写真がまだない場合のデザイン（重要）**
- `photo_url` が空のときは、**シルエットの仮画像を出さない**（今の `assets/img/photo-placeholder.svg` は使わない。ファイルは残してよい）。
- 代わりに、右 6 割を **藍鼠（`#33475B`）の面 + 薄い縦書きのキャッチコピー（または名前）** にして、**それ自体が意図したデザインに見える**ようにする。大きな縦書きの文字（`writing-mode: vertical-rl`）と、細い線程度の装飾だけにする。
- `photo_url` に写真が入ったら、同じ枠が自動で写真になること。`object-fit: cover`、`object-position` を調整しやすいように CSS 変数（例：`--hero-photo-pos`）にする。**人物の顔が切れない**ように、縦長・横長どちらの写真でも破綻しない設計にする（PCは横長寄りの枠、スマホは縦長寄りの枠）。
- 写真が入ったときの確認用に、**テスト用の仮の写真（グラデーションや単色の画像を `photo_url` に入れて表示してみる）** で、PC・スマホの枠の見え方を確認する。※このテスト画像は **コミットしない**。

**見出しまわりのメリハリ（全部同じ調子にしない）**
- 今は「英字の小見出し＋中央揃えの明朝の見出し」が全セクションで同じ。**やめる。**
- セクションごとに構成を変えて、ページにリズムをつける：
  - **ごあいさつ（lead + bio）**：左に大きな見出し、右に本文（PC）。リード文は少し大きめの明朝で。
  - **プロフィール**：項目と内容を表のように並べる（細い線で区切る）。
  - **目指すこと**：**大きな番号（01, 02, 03, 04…）＋左揃えの見出し＋ひと言（summary）＋詳細**。3枚の同じカードを並べるのはやめ、**縦に積むリスト（1行ごとに区切り線）**にする。PCでは左に番号と見出し、右に説明の2カラム。
  - **これまでの活動（年表）**：左に **大きな年（数字）**、右に出来事。縦の細い線でつなぐ。読み飛ばされないように、年と出来事の間に余白をとる。
  - **活動報告**：日付を強調した **リスト形式**（日付／見出し／冒頭の数行）。画像があればサムネイルを添える。**画像がない投稿に「REPORT」の同じ紺色の板を並べるのはやめる**（画像なしなら、文字だけのスッキリした行にする）。
  - **SNS**：控えめに。リンクはシンプルな線のボタン。
- 見出しは、**左揃え**を基本にする（中央揃えは、必要な場所だけ）。
- 大きな文字と小さな文字の差を大きくする（名前や見出しは本文の3〜8倍、補足は小さく静かに）。

**スマホでの見え方（最優先）**
- 閲覧者の多くはスマホ。**390px幅を先に設計**し、PCに広げる。
- タップできる要素は **44×44px 以上**。本文は **16px 以上**。行間 1.8〜2.0。
- 横スクロールが出ないこと（**1280px と 390px、ほかに 360px・768px でも確認**）。
- 日本語の折り返し：`line-break: strict`、`overflow-wrap: anywhere`（URL対策）、見出しは `text-wrap: balance`（効く環境で）。`word-break: auto-phrase` は対応環境のみで効けばよい（なくても崩れないこと）。

**ほかに入れてよいもの**
- スクロールに合わせた、控えめなフェードイン（`prefers-reduced-motion` を尊重）。派手な動き・視差・自動スライドは入れない。
- `<meta name="theme-color">`（背景色に合わせる）。OGP の `og:image` は写真ができてから（今は入れない）。

**やらないこと（「ダサく見える」原因）**
- 仮画像（シルエット）、写真の後ろのずらした板、角丸＋薄い影のカードの並び、水色のグラデーション背景。
- 太字に縁取り・影・グラデーション帯・斜めの帯などの装飾。
- 画像の上に細い明朝の白文字（読みにくい）。
- ファーストビューへの文字の詰め込み。
- どこかのサイトの **レイアウト・画像・文章・ロゴをそのまま真似する** こと（`design-references.md` は「考え方」の参考）。

## 4. 守ること
- **告示前（〜2027年4月1日）なので、投票を依頼する表現は入れない**：「投票してください」「清き一票を」「当選させてください」「お力をください」など。サイトの固定文（`index.html`）も含めて全文を確認する。「応援」「支援」の呼びかけも、**投票依頼と受け取られかねない言い方は避ける**。
- フッターには、**連絡先の表示欄**（事務所のメールアドレス・電話）を必ず残す（選挙期間中の表示義務）。
- 所属政党名・党のロゴ・党の色を **サイトに入れない**。
- 私生活の情報（家族の名前、自宅住所など）は載せない。生年月日も、本人の了承まで載せない。
- アクセシビリティ：本文のコントラスト比 4.5:1 以上、見出しの階層（`h1` → `h2` → `h3`）、画像の `alt`、キーボードだけで全操作できる（フォーカスが見える、スキップリンク、ダイアログ（活動報告）の開閉）、`lang="ja"`、`prefers-reduced-motion`。
- 読み込みを重くしない：画像は `loading="lazy"`（ファーストビュー以外）、`width`/`height` を指定、不要な外部読み込みを足さない。

## 5. 進め方（品質を上げるために）
1. まず、**今のサイトのスクリーンショット（修正前）**を撮る（PC 1280px・スマホ 390px のフルページ）。`docs/research/redesign/before-pc.png` `before-sp.png` に保存する（`docs/research/design-refs/00-*.png` は、ファーストビューだけ）。
2. 作る前に、**短い設計メモ**（ファーストビューの構成、セクションごとの見せ方、CSS変数）を作業用に書き出してから作り始める。
3. 作ったら、**必ず自分の目でスクリーンショットを見て直す**。最低2周する（1周目：崩れ・読みにくさ、2周目：余白・文字の大きさ・リズム）。
   - 確認する幅：**1280px / 768px / 390px / 360px**。
   - 確認する状態：写真なし／テスト写真あり、メルマガ `false`／`true`、活動報告ダイアログを開いた状態、スマホのメニューを開いた状態。
4. コンソールエラーがないこと、404 がないこと（`page.on('console')` と `page.on('requestfailed')` で確認）。
5. `python3 -m http.server` で配信して確認する（`file://` では `fetch` が動かない）。
6. **Google Fonts が読み込めない環境の場合**：この作業環境はネットワークが制限されていることがある。フォントが読み込めない場合、スクリーンショットは代替フォントになり、見た目の確認が正しくできない。その場合は、環境の許可ホスト（`fonts.googleapis.com` と `fonts.gstatic.com`）を `update_environment` で提案して、ユーザーの承認を得る。許可がもらえない場合は、フォントの確認ができなかったことを報告に書く。

## 6. 確認の成果物
